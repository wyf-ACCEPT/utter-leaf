# Phase 2 · 会议转录实施

2026-10-26，用户确认：说话人分离是必需能力，跨会议身份使用豆包托管声纹；会议音频保留本机、手动删除；目前没有 TOS 桶，先使用 HTTPS 签名 URL 注册入口。不搭建账户或统一服务端。

## 当前闭环

「会议」一级入口 → 选择麦克风或麦克风＋系统音频 → 新会议 → 随手笔记、暂停/继续 → 结束并保存 → 完整说话人转录 → 可选逐句整理、Brief → 回听/修正/复制。

- 原生 AVAudioEngine + ScreenCaptureKit，不引入声纹模型或 SDK。系统音频覆盖系统播放来源（排除言叶），并非识别某个会议窗口的参会人列表。使用前关闭无关音源；耳机有助减少麦克风拾取远端声音造成的回声。
- 单场初版上限 3 小时，与五分钟 Fn 听写分开。音频分轨写入 Application Support/UtterLeaf/meetings/<UUID>/，目录 700、文件 600；暂停不采集进文件，完整 WAV 以小块混合生成。该目录排除系统备份。无视频、截图或私人窗口标题存储。
- 实时字幕可关闭，启用会另计流式费用，系统音频和麦克风各一条流。其说话人编号仅为临时标签，不跨音轨/暂停认同一人；网络失效不丢弃磁盘录音。
- 会后文件 ASR 使用 enable_speaker_info + show_utterances + 长会议 ssd_version=300（不足三分钟按官方建议使用 200），单次传入最多 50 个启用声纹。整场识别避免简单拼接分段 speaker 1。低置信度/未知说话人不猜姓名，支持本场改名、合并显示名与单句归属覆盖；原始识别 JSON 保留。
- 每句有稳定 uN ID、起止时间。原始转录不因逐句整理改变；JSON 输出校验每条原 ID 恰好出现一次。Brief 独立会议 prompt，与听写 v6 分开，输入明确作为 JSON 数据，保留原文引用；引用缺失或不存在时不把该结果认作完成。长转录分段整理，分段笔记先保留后合并。
- 文字编辑短暂防抖保存，切换/退出先保存；录音每 5 秒检查写入。中断记录可恢复原始音轨；文件 ASR 请求 ID 在发送前保存，结果未知先查询，不自动重发。用户停止等待不等于服务端取消或免费。
- 录音、文字和调用回执独立。删除音频保留文字；删除会议内容保留 API 用量。听写设置中的正文清除只影响听写，会议由其页面管理。

## 跨会议声纹

豆包 ASR 的声纹管理使用个人 DOUBAO_API_KEY；不使用另一套 RTC RegisterVoicePrint 接口。入口可刷新云端名单、启停下一场候选、改名、以 5–30 秒清晰单人音频签名 URL 注册、软删除。

声纹 ID 与姓名存本机，注册音频和向量由供应商保留；本机不下载向量。签名 URL 是短期访问凭据，使用 SecureField，仅在本次操作内存中存在，不写日志或账本。注册未知结果的标记会持久化，要求先刷新名单再尝试，避免盲目重复创建。删除为供应商软删除（不再查询/匹配），不承诺物理擦除。修改姓名不会自动改写历史会议快照。

尚未配置私有音频上传，不会把本机样本自动公开上传；需要用户提供已有签名 URL。声纹注册和跨会识别实际验收需有效样本及账户权限。

## 接口事实与边界

- 官方文档：说话人分离 https://docs.volcengine.com/docs/DoubaoVoice/speaker-separation?lang=en
- 声纹管理 https://docs.volcengine.com/docs/DoubaoVoice/voiceprint-registration-management-api?lang=zh
- Apple 采音 https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-in-macos
- 实际 ASR 返回的 speaker 位于 utterances[].additions.speaker；同时兼容文档中的 speaker_id。不能只根据文档字段宣布通过。
- 声纹入口实际要求 /api/proxy/invoke/ 末尾斜杠，无斜杠返回同站 307；客户端仍不自动跟随携带密钥的重定向。只在固定官方域名、已验证的规范 URL 请求。
- 文件 ASR 的 audio.data 仍为此前实测的实验兼容路径，官方主要列 URL。长录音请求体以分块 Base64 写磁盘，再用文件上传，避免整场音频/JSON 常驻内存；若接口不支持，显示错误并保留原音频，不自动公开上传。
- 价格沿用用户当前流式/文件与 DeepSeek 单价快照，声纹接口暂无核实费率，金额保留未知。真实会议、长时恢复、系统采音设备与跨会议实名匹配，需要分别验收，短合成 API 检查不能证明它们都已通过。

## 本轮验证

89 项自动测试通过，包括说话人字段兼容、会话身份隔离、原始归属保护、JSON 整理 ID 完整性、原文引用校验、音轨对齐和磁盘恢复、Base64 多块边界、请求恢复只查询不重传、本地损坏文件保护与声纹业务错误。

短合成双人录音真实调用：文件 ASR 成功，返回 3 条发言、2 个说话人；逐句整理返回 3 条对应 ID；Brief 引用有效；声纹名单读取成功（当前为空）。此前按长音频参数测试短音频只返回 1 位说话人，已按官方建议对不足三分钟使用 200 后重试通过，不能隐去这一差异。

这些结果不等于已完成三小时真人会议、系统采音授权、双人抢话、跨会议实名识别或声纹注册/删除验收。当前尚无注册样本签名 URL，故未创建、改名或删除任何真实声纹。原始试用回执留在 Git 忽略的 .local/verification/meeting-smoke/，不提交录音或全文。

本机短采集验收：首次授权尚未生效时失败且未发出 ASR；系统设置显示开启并重启后，麦克风＋系统音频采集成功。使用 QuickTime 播放合成片段，实际保存 40.08 秒，系统/麦克风原始轨均有非零采样，暂停/恢复、随手笔记保存、会后 2 位说话人、逐句整理及 Brief 在原生界面通过。测试会议保留，未删除用户资料。长会与跨会议实名识别仍待独立验证。

用量整合：会议仅向共享账本写匿名计数/时长元数据，正文留在会议存储。会议时长与文字量参与总单位成本，避免只加费用不加分母；短听写的“已写字数”和字数预算投影排除会议，会议消费仍从共享费用预算扣减。音源和实时字幕选择持久化，菜单栏显示录音计时。
